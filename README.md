# MUTI — Music Taste Identity

음악 취향 40문항을 통해 MUSIC 5요인 점수를 계산하고, 닮은 장르·아티스트·추천곡·성격 해석을 보여주는 가벼운 바이럴 웹 테스트입니다. 한국어·영어·일본어를 지원하며 별도 계정이나 백엔드 없이 정적 사이트로 동작합니다.

## 주요 흐름

- 개인 테스트: 설문 → MUSIC 점수 → 장르·아티스트·추천곡·성격 결과
- 친구 궁합: 내 결과 → 초대 링크 → 친구 테스트 → 2인 취향 비교
- 공유: 개인 결과 카드와 2인 궁합 카드를 이미지 또는 결과별 동적 미리보기 링크로 공유
- 탐색: 설문 없이 34개 장르의 성향과 대표 음악 확인, J-pop 장면별 아티스트 발견
- 최근 결과: 브라우저에 최근 결과를 최대 3개까지 저장

## 친구 궁합 데이터 방식

친구 궁합에는 데이터베이스를 사용하지 않습니다. MUSIC 점수는 URL fragment에 버전이 포함된 압축 형태로 저장됩니다.

```text
#compare=v1.82.46.74.31.68
#compare=v1.82.46.74.31.68&guest=v1.70.61.79.48.75
#compare=v1.82.46.74.31.68&guest=v1.70.61.79.48.75&hv=2&gv=2
```

친구 궁합의 앱 내부 결과는 URL fragment로 복원하며 이름, 이메일 같은 개인 식별 정보는 링크에 포함하지 않습니다. 실제 공유 링크는 `/share?host=...&guest=...` 형태로 발급됩니다. 새 개인 결과는 `/result?score=v1...&sv=3&lang=ko`를 사용합니다. 기존 `sv=2` 공유 링크는 당시 32개 장르와 기존 계산식을 유지해 같은 결과를 보여줍니다. 두 공유 경로는 Cloudflare Pages Function을 거쳐 결과별 SNS 미리보기 카드와 메타데이터를 제공한 뒤 브라우저를 앱 결과로 이동시킵니다.

## 점수 해석

- 친구 궁합 링크는 각자의 결과 버전도 보존합니다. `hv=2`/`gv=2`는 구버전 개인 결과이며, 생략한 경우 기존 궁합 링크와 같이 현재 버전 3을 사용합니다.
- 궁합 화면의 참여자는 링크를 누가 열어도 ‘초대한 사람 / 응답한 사람’으로 구분합니다. 양쪽의 장르·음악 캐릭터·개인 결과를 모두 볼 수 있고, 축별 답변 해석과 함께 음악을 고르는 제안을 제공합니다.
- 직접 만든 초대는 친구에게 보내기가 우선이며, 받은 초대는 저장된 개인 결과가 있을 때 바로 비교하기가 우선입니다. 초대 생성 문맥은 해당 브라우저 히스토리에만 남기며, 점수 일치로 참여자의 신원을 추측하지 않습니다. 다른 저장 결과와 각자의 구버전도 선택할 수 있습니다.
- 개인·궁합 결과의 공유 메뉴를 통일했습니다. 링크 전송, 9:16 스토리 카드, 이미지 저장, 링크 복사를 메뉴에서 선택합니다. 모바일 파일 공유용 이미지는 미리 준비하며 실제 게시와 제공되는 앱 목록은 사용자의 기기 환경에 따라 다릅니다.
- 궁합 추천곡은 가까운 상위 3개 장르의 검수된 곡 안에서 교체할 수 있습니다. 공통곡·각자의 소개곡 역할과 점수는 유지하며 다른 슬롯과 중복되지 않습니다. 곡 선택은 현재 화면에만 적용되고 링크 재진입 시 기본 추천으로 돌아갑니다.
- 개인 추천도 대표 입문곡은 고정하고, 인접 장르의 발견곡과 장면별 교차 추천을 교체할 수 있습니다. 34개 장르 모두 2020년대 발견곡·녹음을 기본 노출하며 기존 명곡은 대안으로 보존합니다. 점수·타입·URL은 바꾸지 않고 피드백에는 현재 보이는 곡을 반영합니다. 클래식 등 녹음 크레딧이 있으면 작곡가·연주자 정보를 결과 카드에도 표시합니다.
- 접힌 피드백 입력란은 개인 결과의 장르·캐릭터·추천곡을 별도로 평가하고, 궁합에서는 설명·추천곡을 평가합니다. 입력은 저장·자동 전송하지 않으며 사용자가 전달할 내용을 미리 보고 복사합니다. 원점수나 공유 링크는 피드백 보고서에 넣지 않습니다.
- 점수 일치·전 축 차이·동점 축을 별도로 처리합니다. 동일 점수의 최근 개인 결과도 다른 사람의 프로필일 수 있으므로 궁합에 재사용할 수 있습니다.
- 최근 궁합은 `muti-recent-comparisons-v1`에 점수와 각자의 결과 버전만 최대 3개 저장합니다. 인트로에서 재진입하거나 개별 삭제할 수 있으며 개인 결과 이력은 별도로 보존됩니다. 저장소가 차단되어도 검사와 링크 복원은 동작합니다.
- 함께 들을 장르는 각자의 유사도 중 낮은 값을 우선해 정렬합니다. 세 곡은 함께 시도할 입문곡과 초대한 사람·응답한 사람의 소개곡으로 구성하고, 각자의 장르 유사도를 따로 표시합니다. 두 사람 모두 충분히 가까운 장르가 없다면 입문곡은 발견곡으로 안내합니다. 실제 곡 선호를 예측한 점수는 아닙니다.
- 인트로·검사·결과·탐색·궁합 사이의 이동은 브라우저 히스토리와 연결됩니다. 뒤로가기·앞으로가기 시 진행 중 답변과 결과 버전을 복원합니다.

- 각 5점 응답을 0–100으로 바꾸고 역문항을 뒤집은 다음, 문항 가중치 합으로 나누어 MUSIC 다섯 점수를 계산합니다. 현재는 성향마다 8문항입니다.
- 새 장르 추천(`v=3`)은 자기보고 MUSIC 점수와 정적으로 작성된 장르 프로필을 비교합니다. 다섯 점수 차이의 제곱평균제곱근(RMS)을 100에서 빼 **장르 프로필 유사도**로 표시합니다. 큰 차이는 더 크게 반영합니다. 기존 결과(`v=2`)에는 코사인·유클리드 혼합 점수와 15–95 표시 범위를 그대로 적용합니다. 어느 쪽도 해당 음악을 좋아할 확률이나 통계적 신뢰도가 아닙니다.
- 반올림된 표시 점수가 같아도 실제 유사도가 높은 장르가 먼저 나옵니다. 브라우저와 Cloudflare의 공유 미리보기는 같은 점수·정렬 함수를 사용합니다.
- 인기도·에너지·긍정성·어쿠스틱 값과 성격 해석은 추천 장르의 편집 프로필이지 사용자 개인 점수가 아닙니다. 학술적 신뢰도·타당도가 검증된 성격 진단으로 소개하지 않습니다.
- 34개 장르의 한·영·일 상세 해석은 음색·리듬·곡의 전개·감상 장면 중심으로 제공합니다. 실제 성격이나 파트너 선호를 단정하지 않으며, 고정된 성격 특성 숫자는 화면에 표시하지 않습니다.
- 설문 문구가 바뀌면 진행 중 답변은 이전 문항과 혼용되지 않도록 초기화됩니다. 기존 `v=2` 공유 링크와 최근 결과는 기존 추천식·장르 집합으로 복원합니다. 새 설문 결과는 `v=3`으로 저장합니다. 이후 장르 프로필 자체를 수정할 때는 별도의 결과 버전과 회귀 검증이 필요합니다.
- [연구 대조 및 검증 기록](docs/research-audit.md)에 논문과 구현의 일치 범위, 아직 검증되지 않은 주장, 다음 사용자 테스트 기준을 기록했습니다.

## 화면과 접근성

- 중앙정렬 히어로와 캔버스 도트 배경을 유지하며, 텍스트 뒤의 대비와 공통 카드·버튼·입력 컨트롤을 정돈했습니다. 결과의 장르별 배경색은 페이지 길이가 아니라 고정된 영역에 은은하게 표시합니다.
- 개인·궁합 결과의 섹션 바로가기는 실제 섹션 앵커로 이동합니다. 상세 성격 해석은 기본 펼침이며, 모바일 고정 액션 아래로 마지막 내용이 가려지지 않도록 안전 영역 여백을 둡니다.
- 설문의 클릭·숫자 키 자동 전환은 유지합니다. 방향키는 응답 선택만 옮기고 Enter·Space·다음 버튼으로 확정하므로 탐색 중 문항이 넘어가지 않습니다. 응답 그룹은 질문 제목과 연결하고 진행률에는 실제 응답 수를 제공합니다.
- 모바일 공유 메뉴는 하단 패널, 데스크톱은 중앙 대화상자로 표시합니다. 모달의 키보드 포커스 순환·Escape 닫기·열었던 버튼으로 초점 복원을 유지합니다.
- 모바일 입력은 16px 이상이며 좁은 화면의 분류·정렬은 세로로 배치합니다. 일본어의 긴 텍스트, 감소된 모션 환경, 필터 초기화도 회귀 테스트로 확인합니다.
- 언어 선택·결과 바로가기·저장 이력 펼침은 최소 44px 터치 영역을 제공합니다. 홈의 긴 이력을 펼쳐도 도트 캔버스는 화면 높이로 제한하며, 탭이 숨겨지면 애니메이션을 멈추고 실행 중 모션 설정 변경도 반영합니다.
- 레이더 차트는 좁은 화면에서 축 글자가 잘리지 않도록 반경을 조절하고 전체 축 이름·점수를 두 열 범례로 보여줍니다. 정적 장르 차트와 모션 감소 환경에서는 실제 데이터 도형도 애니메이션 없이 표시합니다.
- [최종 UI·기능 보완 기록](docs/final-ui-functional-check.md)에 이번 수정과 검증 범위를 기록했습니다.

## 기능 복구와 결과 관리

- 결과 섹션 바로가기는 URL이나 히스토리를 변경하지 않고 해당 섹션으로 스크롤·포커스 이동합니다. 특히 궁합의 점수가 담긴 fragment를 덮어쓰지 않아 새로고침·뒤로가기에도 두 사람의 결과가 보존됩니다.
- 개인 최근 결과는 점수뿐 아니라 결과 버전까지 포함해 중복을 판별합니다. 같은 점수의 구버전·신버전 해석을 각각 보관하며, 잘못된 저장 데이터나 지원하지 않는 버전을 현재 결과로 재해석하지 않습니다. 개인 결과도 개별 삭제할 수 있고 다른 탭의 저장·삭제는 첫 화면에 반영됩니다.
- 설문의 손상된 저장 단계는 유효한 응답을 보존해 복원합니다. 브라우저 단축키·IME 입력·키 반복은 답변으로 처리하지 않습니다.
- 첫 화면에서 진행 중 응답이 있으면 이어서 검사할지 처음부터 시작할지 선택합니다. 초안은 같은 탭의 `sessionStorage`에만 보관하며, 궁합 검사 재개 시에는 검증된 초대 맥락도 유지합니다. 진행률은 현재 문항 위치가 아니라 유효하게 답한 문항 수로 계산합니다.
- 장르 탐색은 세 언어의 장르명과 카탈로그 아티스트·앨범·곡명을 함께 검색합니다. 띄어쓰기·문장부호·전각 입력 차이를 정규화하며, 검색한 아티스트는 상세창에서도 찾을 수 있습니다.
- 검색어 지우기·필터 초기화 후 검색 필드에 초점을 유지합니다. 저장 결과 삭제 후에는 남은 결과나 검사 버튼으로 초점을 옮기고, 저장소가 삭제를 거절하면 기존 결과를 유지하며 실패를 안내합니다.
- 공유·피드백 복사는 단일 작업만 실행하고 진행 상태를 표시합니다. 연속 탭으로 중복 공유·캡처가 발생하지 않으며 복사 중 피드백을 수정하면 새 초안을 복사했다고 잘못 안내하지 않습니다. 궁합 추천곡에도 개인 결과와 동일하게 앨범·녹음 크레딧과 곡 교체 안내를 표시합니다.
- 기기의 파일 공유 실패는 이미지 생성 실패와 구분합니다. 완성된 PNG를 재생성하지 않고 사용자 재클릭으로 직접 저장할 수 있으며, 공유 취소 시 자동 다운로드하지 않습니다. 클립보드가 차단되면 명시적인 복사 시도 후 선택 가능한 결과 링크와 점수 포함 안내를 제공합니다.
- 친구 초대도 공유·복사 실패 후 직접 선택할 수 있는 링크를 제공합니다. 피드백 복사 실패 시에는 미리보기를 펼치고 보고서 전체 선택을 제공합니다. 선택만으로 클립보드 쓰기·전송·저장을 실행하지 않습니다.
- 받은 초대의 전송 버튼은 ‘받은 초대 전달’로 표시합니다. 공유 문구와 안내에서도 원래 초대한 사람과 비교하는 링크임을 구분하며, 전달할 때 원본 점수·버전을 보존합니다.
- 개인·궁합 최근 결과 저장이 실패하면 해당 결과에만 안내합니다. 사용자 클릭으로 정확한 버전·언어의 결과 링크를 표시하며, 수동 보관 전에 링크에 취향 점수가 들어 있음을 안내합니다.
- 검사·결과·탐색·초대·궁합 화면의 렌더링과 화면 파일 로딩 오류는 복구 화면으로 처리합니다. 다시 시도·홈 복귀는 사용자가 선택하며 초안·결과 URL을 보존합니다. 실패한 파일 요청이 런타임에 캐시되는 경우 사용자 재시도 클릭에서만 페이지를 새로고침합니다. 초기 질문·장르·카탈로그 데이터 로딩에도 같은 정책을 적용합니다.

## 배포 갱신과 오프라인 범위

- 온라인 홈 화면과 고정 주소의 공개 자산은 최신 응답을 우선합니다. 홈 HTML과 그 HTML이 참조하는 JS·CSS가 준비된 뒤 오프라인 홈 스냅샷을 갱신합니다.
- 점수 쿼리·공유 미리보기·API 응답·Next.js 데이터 응답은 오프라인 캐시 대상이 아닙니다. 점수가 담긴 링크로 온라인 접속한 응답을 홈 캐시에 저장하지 않습니다.
- 서비스 워커 갱신 때문에 검사 중인 페이지를 강제로 새로고침하지 않습니다. 이미 방문해 준비된 화면은 오프라인 재방문을 지원하지만, 최초 방문 직후 아직 불러오지 않은 모든 화면이나 외부 Spotify 재생·SNS 공유까지 오프라인 동작을 보장하지 않습니다.
- 브라우저 테스트는 임시 원본 서버의 실제 연결 장애로 캐시 복원을 검증합니다. WebKit 오프라인 에뮬레이션의 한계와 실기기 확인 범위는 [PWA 검증 기록](docs/pwa-cache.md)에 명시했습니다.

## 기술 구성

- Next.js 15 / React 19 / TypeScript
- Tailwind CSS 4 / Framer Motion / Recharts
- `html-to-image` 기반 공유 이미지 및 iOS 파일 공유 시트 지원
- Cloudflare Pages Functions 기반 동적 SNS 미리보기 카드
- 개인 결과의 장르·타입명·일치율을 반영하는 전용 Open Graph 이미지
- Node 단위 테스트와 Playwright 모바일 E2E 테스트
- 정적 JSON 기반 질문·장르 데이터
- 34개 결과 장르, 81개 장르별 추천과 7개 교차 추천으로 구성된 정적 음악 카탈로그
- 재즈 힙합·멜로딕 댄스 결과 타입과 J-pop·K-pop·글로벌 팝 교차 추천. J-pop은 단일 사운드 유형이 아닌 탐색 장면으로 취급
- 런타임 API 호출 없는 Spotify 직접 곡 링크(장르 탐색에는 앨범 링크)
- 정적 export 및 PWA 지원

## 로컬 실행

```bash
npm install
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다.

## 검증 및 빌드

```bash
npm run lint
npm run test:unit
npm run validate:catalog
npm run build
npm run test:e2e
```

`npm run build`는 정적 결과물을 `out/`에 생성합니다.

`npm run validate:catalog`는 모든 장르에 단일 `anchor`와 2020년대 `discovery`가 있는지, 장르별 2–4개 제한, Spotify 앨범·곡 URL 형식과 중복 여부가 올바른지 확인합니다. 카탈로그는 `src/data/musicCatalog.json`에서 관리하며 Spotify Web API나 사용자 로그인을 사용하지 않습니다. 현대 발견곡은 최신 차트 순위나 유행을 보증하는 표기가 아닙니다. 전체 매핑과 편집 근거는 [카탈로그 검수 기록](docs/music-catalog-review.md)에 정리했습니다.

외부 링크를 실제로 검수할 때는 `node scripts/audit-spotify-tracks.mjs --mismatches`를 실행합니다. Spotify의 공개 앨범 임베드에서 88개 앨범을 읽어 추천곡 ID의 수록 여부와 실제 곡 제목·앨범 판본 제목·아티스트 크레딧을 대조합니다. 일시적 장애는 두 번까지만 재시도하고 불일치나 최종 네트워크 실패가 있으면 종료 코드 1을 반환합니다. 국가·계정별 재생 가능 여부까지 보증하는 검사는 아닙니다.

`npm run test:unit`는 역채점·가중 평균·점수 범위·동점 정렬과 34개 장르의 한·영·일 결과 콘텐츠, 40개 일본어 문항, 공유 이미지 글리프의 완전성을 검증합니다.

`npm run test:e2e`는 정적 빌드와 Cloudflare Pages Functions를 함께 실행해 다음 흐름을 모바일 Chromium에서 검증합니다.

- 친구 초대에서 40문항 완료 후 궁합 결과 표시
- 궁합 결과 링크 및 개인 결과 복원
- 개인·궁합 결과 카드의 PNG 저장
- 동적 Open Graph 메타데이터와 1200×630 이미지
- 한국어·영어·일본어 공유 미리보기 및 링크 진입 언어 유지
- 브라우저 저장소 접근이 차단된 환경에서의 검사 완료·결과 복원
- 설문 자동 진행·답변 수정, 결과 본문 완전성, 장르 상세의 키보드 조작

Pull Request와 `main` 브랜치 push에서도 같은 E2E 검증이 GitHub Actions로 자동 실행됩니다.

iPhone Safari에 가까운 WebKit 회귀 검사는 선택적으로 `npx playwright install webkit` 후 `MUTI_WEBKIT=1 npm run test:e2e -- --project=mobile-webkit`로 실행합니다. WebKit에서는 파일 공유 시트를 모의해 탭 순간의 이미지 전달을 확인합니다. 실제 iPhone의 공유 시트·Instagram 게시와 사진 저장은 [iPhone 실기기 점검표](docs/ios-smoke-checklist.md)로 별도 확인해야 합니다.

추천과 문항의 실제 일치·불일치는 [사용자 피드백 점검표](docs/user-feedback-checklist.md)로 확인합니다. 자동 테스트 통과를 실제 음악 선호나 성격 정확도의 검증으로 해석하지 않습니다.

## Cloudflare Pages 배포

- Build command: `npm run build`
- Build output directory: `out`
- Functions: 저장소의 `functions/` 디렉터리에서 자동 배포
- Function routes: `/share`, `/result`, `/api/og`만 `public/_routes.json`에 포함
- 공개 도메인: `https://muti.chameleonstudio.xyz`. Squarespace DNS의 `muti` CNAME은 `musicpersonalitytest.pages.dev`를 가리키고, Cloudflare Pages의 Custom domains에도 같은 주소를 등록해야 HTTPS 인증서가 발급됩니다.
- `NEXT_PUBLIC_SITE_URL`: canonical URL, 구조화 데이터, robots.txt, sitemap.xml, 정책 페이지의 사이트 주소를 정합니다. 설정하지 않으면 `https://muti.chameleonstudio.xyz`를 사용합니다. Cloudflare Pages에 예전 주소가 설정돼 있다면 이 값도 새 주소로 갱신하고 다시 빌드하세요.
- `NEXT_PUBLIC_ADSENSE_ENABLED=false`: AdSense 스크립트를 빌드에서 제외합니다. 설정하지 않으면 기존처럼 로드됩니다. 인증 CMP 설정 전 광고를 잠시 끄고 배포할 때 사용할 수 있습니다.

나머지 앱과 정적 자산은 Pages에서 그대로 제공되므로 데이터베이스나 별도 이미지 렌더링 서비스가 필요하지 않습니다. 한국어·일본어 공유 이미지는 미리 생성한 비트맵 글리프를 커밋해 Cloudflare Workers의 폰트 엔진 없이 렌더링합니다. 한국어는 [Pretendard](https://github.com/orioncactus/pretendard), 일본어는 [Noto Sans JP](https://github.com/notofonts/noto-cjk)의 OFL 폰트로 생성했습니다. 장르명·유형명을 추가한 경우 한국어는 `npm run generate:og-glyphs -- /path/to/Pretendard-Bold.otf`, 일본어는 `npm run generate:ja-og-glyphs -- /path/to/NotoSansJP-VF.ttf`로 다시 생성한 뒤 `npm run test:unit`으로 누락 여부를 확인하세요.

## 데이터와 개인정보

- 설문 계산과 추천은 모두 브라우저에서 처리됩니다.
- 최근 결과와 자체 이벤트 기록은 브라우저 `localStorage`에만 저장됩니다. 저장소가 차단된 환경에서도 검사는 계속되지만 최근 결과와 진행 상황은 보존되지 않습니다.
- 서비스는 계정·결과 데이터베이스를 사용하지 않습니다. 다만 SNS 미리보기용 공유 링크를 열면 MUSIC 점수가 URL 쿼리에 포함되어 Cloudflare Pages Function과 링크를 받은 서비스에 전달될 수 있습니다. 공유 전 이 점을 확인해야 합니다.
- 광고가 활성화된 배포에서는 Google AdSense의 별도 데이터 정책이 적용될 수 있습니다.

배포 전 AdSense 계정의 Privacy & messaging에서 EEA·영국·스위스 방문자를 위한 Google 인증 CMP/TCF 메시지 설정을 확인하세요. 광고 스크립트는 기본적으로 로드되지만 `NEXT_PUBLIC_ADSENSE_ENABLED=false`로 제외할 수 있습니다. 계정 측 설정은 저장소에서 검증할 수 없으므로 해당 지역에 광고를 제공할 계획이라면 설정 확인 전에는 배포를 완료된 상태로 간주하지 마세요.
