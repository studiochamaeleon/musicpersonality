# PWA 캐시와 연결 장애 검증

## 동작 범위

- 온라인 홈 탐색은 네트워크에서 최신 HTML을 가져옵니다. 성공한 HTML과 그 HTML이 참조하는 해시 JS/CSS가 모두 준비된 뒤에만 `/` 오프라인 스냅샷을 갱신합니다.
- 네트워크 요청이 실제로 실패할 때 준비된 홈 스냅샷으로 복원합니다. 서버가 반환한 404/500 등을 오프라인 홈으로 감추지 않습니다.
- 검색 매개변수 없는 `/`만 홈 캐시에 보관합니다. 점수가 담긴 URL, `/result`, `/share`, `/api`, RSC 응답, 개인정보/약관 문서를 홈 캐시에 저장하지 않습니다.
- 이전 빌드의 해시 파일을 즉시 제거하지 않아 아직 열려 있는 이전 화면의 파일 참조를 보호합니다. 알려진 MUTI 레거시 캐시만 안전한 마이그레이션 이후 정리합니다.
- 새 서비스 워커는 기존 화면을 강제로 새로고침하지 않습니다. 진행 중인 검사는 유지하고 기본 서비스 워커 업데이트 수명 주기를 사용합니다.

첫 방문만으로 모든 화면의 오프라인 동작을 보장하지 않습니다. 이미 제어되는 온라인 방문에서 로딩된 데이터/지연 화면의 파일만 추가로 보관되므로, 아직 방문하지 않은 화면이나 외부 음악 링크는 연결이 필요할 수 있습니다. 브라우저가 저장소를 비우거나 용량을 제한하면 오프라인 복원 역시 보장되지 않습니다.

## 자동 검증

`tests/unit/serviceWorker.test.mjs`는 최신 스냅샷 교체, 준비되지 않은 빌드의 이전 스냅샷 유지, 동시 요청 순서, 캐시 오류, 개인 URL 제외와 레거시 마이그레이션을 검증합니다.

`tests/e2e/service-worker.spec.ts`는 브라우저별 독립 임시 HTTP 프록시로 앱을 연 뒤 홈과 방문한 검사 화면을 준비하고, 그 프록시의 서버와 연결만 종료합니다. 공유 미리보기 서버는 종료하지 않습니다. 실제 네트워크 연결 실패 후 SW가 반환한 200 응답과 검사 화면 재진입을 확인하며, SW가 없는 대조군은 새 URL 접속이 실패해야 합니다. 온라인 HTML 갱신 및 개인 URL/RSC 캐시 비오염도 검증합니다.

Playwright 1.63.0 / WebKit 2359의 `context.setOffline(true)`는 서비스 워커가 네트워크 없이 직접 만든 응답에도 탐색을 거부하는 [알려진 문제](https://github.com/microsoft/playwright/issues/42775)가 있습니다. 별도 로컬 최소 예제에서 동일 오류를 재현했고, 같은 예제의 서버를 종료하면 SW 응답은 정상 복원됐습니다. 해당 문제의 [수정 PR](https://github.com/microsoft/playwright/pull/42894)은 자동 검증 도구 쪽 변경입니다.

프록시 종료 검증은 실제 원본 연결 장애에 대한 캐시 폴백 검증이며, 실제 iPhone Safari의 비행기 모드·홈 화면 앱 수명 주기·저장소 제거까지 증명하지 않습니다. 출시 전 실제 기기에서 온라인 홈 및 검사 방문 → 홈 복귀 → 비행기 모드 → 다시 열기와 업데이트 중 검사 유지 여부를 별도로 확인해야 합니다.
